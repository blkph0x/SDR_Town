# P25 capture 013124 and SSTV receive audit

Date: 2026-10-11. Baseline HEAD: `1cf9bf9`, with existing local DEC-0212/0213
soft-score and bounded-gain changes preserved. This audit adds DEC-0215/0216.
Private IQ, audio, validation records and intermediate reports remain local.

## Confirmed and repaired

### P25: unbound sync borrowed another slot's clear state

The new per-burst security snapshot exposed a reproducible authorization bug,
not an audio-buffer problem. In the 417.550 MHz / TG12068 / slot 1 replay:

1. The selected slot had no trusted ESS or CRC-valid traffic MAC.
2. Slot 0 recovered clear ESS (algorithm 0x80, 11 corrected RS symbols).
3. An isolated S-ISCH fallback burst had `grantSlotKnown=false`, no applied
   XOR mask, and no voice codewords. The decoder nevertheless passed slot
   0's session into that fallback, attaching its retained clear ESS.
4. Two consumer evidence loops accepted unlabelled ESS as evidence for either
   selected slot. This promoted slot 1's security latch to clear. Subsequent
   labelled slot-1 voice could then pass the clear-call gate.

The fix removes the session from unbound fallback decoding and requires an
identified slot in both followed-slot evidence loops. Valid same-slot retained
security remains intact. No FEC, symbol recovery, vocoder, timeout, buffering,
grant-selection or radio-control parameters changed in DEC-0216.

Reference ownership rule: SDRTrunk's
[P25P2AudioModule.receive](https://github.com/DSheirer/sdrtrunk/blob/master/src/main/java/io/github/dsheirer/module/decode/p25/audio/P25P2AudioModule.java)
checks the message timeslot before processing voice, PTT or ESS. This repair
restores that ownership boundary; it does not claim implementation parity.

The synthetic isolated-sync + valid later superframe test fails before the fix
with three false security assertions, then passes. Real replay falls from 380
frames / 7.60 seconds of unauthorized PCM to zero. The test tool labels this
`FAIL_NO_AUDIO`, correctly indicating that voice was NOT recovered; for this
negative security case, remaining unknown and muted is the required outcome.
It does not establish whether the original selected-slot payload was encrypted.

### SSTV: Auto listening waited for the image header

`SstvRfRouter::pop()` intentionally returns nothing until VIS selects USB, LSB
or NFM. The speaker callback incorrectly depended on that image-decoder queue.
Therefore opening the dedicated radio in Auto could be silent while searching;
after lock it could play retained header pre-roll as delayed audio.

A separate callback now receives fresh 48 kHz monitor samples once, independently
of image pre-roll. Dedicated Auto listens provisionally as USB below 30 MHz or
NFM otherwise; this is a listening convention, NOT a modulation detection claim.
The valid VIS winner takes over after selection. Manual modes remain manual.
Shared-receiver output ownership/muting and the image decoding contract stay
unchanged. Logs distinguish provisional/selected mode and monitor sample count.

## Remaining gaps, not disguised as fixes

- **CC coverage (ISS-0094):** 631 unsubmitted intervals total 67.568 seconds
  while CC processing is enabled. Median gap 64 ms; maximum 1.312 seconds.
  This is separate from 103.060 seconds outside the captured CC passband and
  41.126 seconds with traffic-follow suspension. Missing intervals are NOT a
  count of missed grants. CC decode p95 is 301 ms versus queue p95 0.327 ms.
- **Short PCM tails (ISS-0095):** worker output totals 1,812,480 samples,
  whereas capture/callback consumption totals 1,809,600, a 60 ms difference.
  Follow 7 explicitly retains 40 ms below the startup threshold. The remaining
  20 ms is not conclusively attributed. Normal-end draining needs session-bound
  consumer tests; encrypted, stale-generation and user-stop paths must discard.
- **Clear grant without clear traffic (follow 6):** 9-second replay recovers
  86 selected VCWs and one valid MAC, but no trusted clear ESS/audio. This is
  not evidence that the speaker ring dropped decoded speech. One-second RF
  snapshots show this carrier fades to the local background after about 329 s.
- **Quiet-tail parking / incomplete identity (ISS-0096):** no arbitrary hold
  reduction. A control grant's TG label is not traffic-MAC identity evidence.
- **Per-device gain UI (ISS-0093):** still separate from DSP gain normalization;
  fix requires valid workflow ownership, not choosing the first connected SDR.

Voice worker queue p95 is 0.029 ms; decode p95 116.723 ms and max 255.057 ms;
publication p95 13.515 ms. The capture does not support a minute-long voice
worker backlog explanation. Zero capture loss does not mean every IQ sample
was submitted to every decoder. Empty callbacks during silence are not proof
of speech loss. Local STT produced repetitive generic text for the suspect
audio, which is NOT intelligibility ground truth.
