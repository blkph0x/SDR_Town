# DSP proposal audit - 2026-09-26

## Scope and evidence

Reviewed the supplied "This rewrite uses what the tree does now" proposal against
09cc9dd, application baseline 25236d2 / v0.2.104. This is an evidence review and
repair plan, not a claim that every application path is certified. No production
code, tests, P25 gates, DSP defaults or release binaries changed.

Evidence classes used below: **source-confirmed**, **calculated**, **test-proven**,
and **unverified**. A calculation of a stage is not an end-to-end receiver test.
Existing Release binaries passed all 15 registered CTest suites in 46.48 seconds
on this Windows host. This was a baseline rerun, not a fresh rebuild. The test
runner log is build/Testing/Temporary/LastTest.log (machine-local).

## Confirmed priorities

### 1. FM decimation does not preserve the sample lattice between blocks

**Source-confirmed:** src/Demod.cpp:675 starts NFM's second decimator at index zero
on every call. The WFM speech decimator does the same at line 766. Neither loop
carries its residual phase. NFM's first boxcar does carry its count; WFM's separate
MPX branch also carries mpxPhase. These are materially different implementations.

**Calculated reproduction:** at 2.4 MS/s, C++ rounding selects M1=13, M2=4, giving
46153.8461538462 discriminator samples/s, not exactly 48 kHz. Two contiguous
8192-sample inputs produce 630+630 first-stage samples. Independently keeping
indices 0,4,... produces 158+158 samples. One combined block produces 315, not
316. The selected input indices differ as well. This is a deterministic sample
clock defect for those partitions, not proof that it caused a particular user's
robotic audio. Final resampling cannot reconstruct the lost selection lattice.

**Next repair gate:** run the actual Demodulator on identical FM input with whole,
fixed and irregular block sizes, compare decoder-tap sample counts/indices and
waveforms after one documented startup latency. Persist decimation phase, not
rounded per-block output counts. Test 2.048/2.4/10 MS/s and low-rate input, 44.1/48
kHz output, retunes and changes of rate. Do not change filtering simultaneously.

### 2. FM speech FIRs depend on future samples that are not retained

**Source-confirmed:** src/Demod.cpp:651-667, 692-705 and 724-744 evaluate centred
convolution at n+k, omit out-of-range indices and immediately publish the tail.
The final half-filter of each block is therefore computed without the next
block's input. Prepending previous input does not supply future input. Splitting
the same recording changes these boundary values. In the NFM paths, input history
also remains stale when a block is shorter than D (lines 650, 666, 691, 705).

Use a causal persistent FIR, or explicitly retain a lookahead tail and report its
latency. Tests must include blocks smaller than the filter length. Compare against
a reference convolution and exact sample accounting. WFM/RDS has a separate causal
MPX filter; preserving its output while repairing speech is a specific gate.

### 3. Current FM tests do not exclude either defect

**Source-confirmed:** tests/test_demod.cpp:532 tests two 480-sample blocks at
48 kHz and accepts an endpoint difference below 0.8. It neither exercises the
high-rate decimator nor establishes partition invariance. RMS/finite-output tests
can pass with damaged boundaries. The baseline passing is useful, but insufficient.

**Existing stronger model:** tests/test_hf_demod.cpp:361 compares whole versus
irregular chunks for AM/USB/LSB/CW at both audio rates, asserting equal counts and
maximum waveform error below 1e-5. That test passed in the baseline. Extend the
approach to FM rather than increasing filter lengths first.

### 4. NFM first-stage rejection needs a measured specification

**Source-confirmed:** src/Demod.cpp:597-614 uses a single length-M1 moving average
before downsampling. Once an unwanted signal folds into the wanted band, the
later narrow FIR cannot distinguish it from wanted input at that frequency.

**Calculated:** H(f)=sin(pi*f*M/fs)/(M*sin(pi*f/fs)). At fs=2.4 MHz, M=13 and
f=fs/13+1500 Hz, rejection is approximately 41.789 dB, and the signal folds to
1500 Hz. This is not a measured final audio rejection value. Whether it is enough
depends on blocker power, modulation, desired sensitivity and front-end linearity.

Define those requirements and test actual two-signal IQ fixtures before choosing
a replacement. A higher-order CIC has droop and delay; cascaded independent
integrate-and-dump stages are not automatically the required higher-order CIC.
Polyphase FIR and multistage approaches should be compared for rejection and CPU.

### 5. Fixed output counts can conceal upstream clock problems

**Source-confirmed:** src/Demod.cpp:444-447 rounds a requested block duration;
lines 910-950 interpolate to that count, repeat base.back() for unavailable future
samples and reset some phase excursions. This is not proof of continuous output
timing. Characterize together with findings 1 and 2 before changing this stage.
Do not interpret a full-length PCM buffer as proof that all samples were decoded.

## Corrections to the supplied proposal

| Proposal | Audit result / disposition |
|---|---|
| Move WFM to 192 kHz with a 100-110 kHz low-pass cutoff | Not a safe universal rate plan: 192 kHz complex sampling spans +/-96 kHz. Include passband and transition width and use actual fs/M. Current internal target also depends on BW (Demod.cpp:451), so it is not always 192 kHz. |
| Add filtering before NFM's second skip | A downsampler following an adequate anti-alias filter is valid. First measure existing filter response and fix phase continuity; another filter is not inherently a repair. |
| 70 dB Kaiser means 70 dB rejection | Beta alone does not establish a required transition band or measured stopband; order, rate and cutoff matter. |
| Increase SSB taps from 257 to 401 | Unproven benefit. Current HF opposite-sideband, blocker, AGC, alias and partition tests already pass. Specify rejection/latency/CPU requirements first. |
| Force audioLpfEnabled=false for CTCSS/DCS | Current NFM tone tap is taken before audio LPF/de-emphasis (Demod.cpp:825-858). Speech LPF changes are not needed to bypass a filter that the tap never traverses. |
| SSTV 1200-2300 Hz is blocked by a 4.5 kHz LPF | Incorrect rationale: these frequencies are below that cutoff. Confirm actual mode, filter response and selected tap; do not globally disable speech filtering. |
| NFM has an independent causal MPX filter | Stale description: the independent causal branch is WFM-only (line 523); NFM publishes the speech discriminator tap. It inherits upstream NFM boundary defects. |
| 50-80 ms Goertzel with a sign-inverted hypothesis detects reverse burst | Whole-window sign inversion changes phase by pi, not Goertzel magnitude. Both energy scores are identical. Reverse-burst detection requires phase-relative transition evidence. Short-window discrimination of nearby low tones needs its own false-positive tests. |
| Estimate original occupied bandwidth after narrow channel filtering | That output no longer contains rejected sidebands. Use a pre-narrowing measurement branch with a defined noise/interference estimator. |
| Always 75 us WFM / 750 us NFM | WFM standards permit 50 or 75 us; use the appropriate configured region. Current NFM uses 750 us when its audio LPF is enabled; that implementation choice is not proof of a universal land-mobile standard. |
| Enable live P25 streaming DDC now | Reject for this pass. DEC-0014/0018/0038 record failed continuity gates; header default false is intentional. GUI-only enablement still changes the accepted path. |
| Canonical-only P25 speaker changes now | Separate product/security/cadence work requiring capture evidence and explicit scope. Counters or names alone do not prove that a gate is safe. Preserve P25. |
| Log clock uncertainty from the system clock | Clock timestamps alone do not measure synchronization uncertainty. Log source and unknown uncertainty unless independently measured. |
| Geolocation without shared 10 MHz/PPS is illegal | No legal basis supplied. Reliable geolocation needs a validated synchronization/calibration/error model appropriate to the technique; those particular clock connections are not a universal legal requirement. |

## Other chains: verified contracts and remaining evidence

- **HF:** HfDemod handles AM/USB/LSB/CW via early dispatch in Demod.cpp:425.
  Its existing 257/401-tap design is not itself evidence of poor performance.
  AM selective-fading and noisy off-tune field acceptance remain different from
  the passing synthetic carrier-normalization tests. Sync AM, adjustable CW pitch,
  IF shift and stereo WFM are feature proposals, not repairs established here.
- **RDS/tones:** src/ReceiveDecoder.cpp:15-17 declares MPX 128-384 kHz and
  tone/discriminator 8-96 kHz. requiredModule is explicitly not an availability
  probe. The adapter checks domain, rate, block size, source and discontinuity.
  Do not equate registry presence with an installed backend or RF acceptance.
- **CTCSS:** current decoder uses windowed energy, candidate separation and two
  matches (CtcssDecoder.cpp:66-89). A new short-burst engine needs labelled adjacent
  tone, voice-only, noise, reverse-burst and rate-change fixtures, not only clean
  generated tones. Physical tester verification remains necessary.
- **SSTV:** RF, GUI, transport, rate and mode tests exist. All registered tests
  passed, but that is not proof of every SSTV mode over every real RF path. Keep
  HF/NFM tap contracts and image quality fixtures in the regression matrix.
- **Inmarsat:** InmarsatPipeline.cpp:57-86 rejects invalid rates and channels whose
  native filter extends outside IQ coverage. InmarsatWatch.cpp:251 catches worker
  exceptions. Existing replay/live-GUI fixtures passed. A constellation/probe lock
  is still not validated messages, aircraft identity or intelligible voice.
  The already-recorded 10 MS/s processing overload and per-device ownership work
  remain higher priority than speculative receiver-wide filter replacement.
- **ADSB/APT:** the proposal supplies no measured evidence justifying a capacity
  increase or new acceptance claims. Neither a cap increase nor calibration/TLE
  feature is approved by this audit. Require overflow/latency and actual decode
  fixtures respectively; these branches were not exhaustively re-audited here.
- **Remote diagnostics:** ISS-0035 still separates shipped client opt-in from
  production collector deployment, retention and per-install authentication.
- **Rotator/SWR:** ISS-0036 remains hardware acceptance, not synthetic receive DSP.

## Ordered next implementation passes

1. Add actual FM characterization fixtures for findings 1/2/5 without changing DSP.
   Record counts, maximum/RMS error, boundary-local error and real-time CPU ratio.
   Include both speech and decoder taps and isolate expected current failures.
2. Repair NFM persistent decimation phase alone, then FIR history/lookahead alone.
   Do not simultaneously change bandwidth, de-emphasis, squelch or AGC. Obtain a
   decision for the protected shared file; never weaken the frozen-P25 guard.
3. Establish blocker masks and measure NFM rejection. Select a replacement only
   from measured alias rejection, passband droop, latency and throughput results.
4. Characterize WFM separately; preserve existing RDS reference decode and speech
   fixtures. Do not make WFM the first rewrite just because a proposal ranks it so.
5. Improve tone burst detection, HF features and stereo in isolated changes only
   after their input-stream invariants and acceptance fixtures are established.
6. Profile Inmarsat channel fan-out and complete ownership/diagnostics acceptance
   separately. Archive provenance, format, stream identity and timebase metadata
   are additive work, not grounds to rewrite the P25 capture path.

For shared-chain changes, run all dependent demod/tone/RDS/SSTV and full registered
tests, protected-path review, representative replay comparisons, then live tester
acceptance. A family-only test or RMS check is insufficient. No finite suite can
guarantee zero regressions; narrow patches and explicit acceptance evidence reduce
that risk. Do not alter the accepted P25 path for this programme.
